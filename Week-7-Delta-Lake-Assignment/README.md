# Week 7 - Delta Lake SCD Assignment

This project implements a simple Delta Lake customer dimension pipeline using the provided Superstore-style dataset.

## Project Objective

The goal of this assignment is to understand how Delta Lake can be used for incremental customer data processing and Slowly Changing Dimensions.

The project covers:

1. Loading customer master and incremental CSV files.
2. Cleaning customer records by removing duplicates and handling blank values.
3. Creating Delta tables from CSV data.
4. Applying SCD Type 1 updates where the latest record overwrites old values.
5. Applying SCD Type 2 updates where customer history is preserved.
6. Running validation checks to confirm the final output is correct.

## Dataset Details

The original dataset contains order-level records with customer, product, sales, quantity, discount, and profit details. For this assignment, the data has been converted into two customer-level files:

- `customer_master.csv`: initial customer records used to create the starting Delta table.
- `customer_incremental.csv`: new and updated customer records used for SCD processing.

Some incremental records are intentionally updated so that both SCD Type 1 and SCD Type 2 logic can be demonstrated clearly.

## SCD Type 1 Explanation

SCD Type 1 keeps only the latest version of a record. If a customer's city, segment, or region changes, the old value is overwritten.

This is useful when historical tracking is not required.

## SCD Type 2 Explanation

SCD Type 2 keeps historical versions of records. If a customer's important details change, the old row is marked as inactive and a new current row is inserted.

The notebook uses these columns for SCD2 tracking:

- `effective_start_date`
- `effective_end_date`
- `is_current`
- `record_hash`

## Validation Performed

The notebook checks:

1. SCD1 has no duplicate customer IDs.
2. SCD2 has only one current row for each customer.
3. SCD2 creates history rows for changed customers.
4. Final outputs are saved for review.
